# 第三次延期：家长审批

用户已确认：孩子自主延期最多 2 次；用完后这一轮只能额外申请一次，等待家长审批期间允许继续玩。第三次获批时长沿用本轮家长设置，仍不超过 15 分钟；不开放第四次申请。

## 家长在哪里配置

1. 进入孩子详情的“闸门规则”，设置连续使用多少分钟开始答题。
2. 在“游戏与应用”设置提前提醒秒数、单次延期 1—15 分钟、自主延期最多 0—2 次，并开启游戏模式。家长可收紧自主额度，额度用完后提供本轮一次额外审批。
3. 同一页面的“额外延期申请”查看设备、游戏包名、本轮规则版本、申请时刻和申请时长，点击同意或拒绝。
4. 页面区分“已同意，等待手机确认”和“手机已执行”；审批列表每 5 秒刷新。首版不增加短信、微信或其他外部推送。

当前周期冻结规则，家长修改配置从下一轮生效；审批展示和采用当前周期原有时长，不把刚修改的下一轮时长套到旧申请。

## 孩子端流程

- 自主额度尚有剩余：提醒窗提供原有“延长”按钮。
- 自主额度耗尽：提醒窗提供“向家长申请”按钮。先保存申请状态，再发送；只有服务端确认已收到申请，才进入允许继续玩的等待状态。发送失败不增加时间，可在原时间内重试。
- 已提交且等待中：显示等待家长的提示，继续记录真实游戏用量，不在原时限结束时强制答题。按用户选择，本版不另设审批超时；已进入等待后断网，会保持等待直到重新联网取得结果。
- 家长同意：原有时间尚未用完时，将批准时长接在后面；已经超出原时限时，从收到批准起给满本次游戏时长。先持久化批准结果，再更新界面，并向服务端确认执行；重复结果不会重复增加时间。
- 家长拒绝：不补时间，按原时限执行；原时间已经用完则进入答题。熄屏或离开游戏时，返回游戏再按本轮状态执行。
- 等待时孩子也可选择现在答题，此时关闭本轮申请；答对结束本轮，恢复下一轮额度。迟到的旧周期批准不能给下一轮加时间。
- 同一轮切换游戏、熄屏、进程或设备重启，保留周期编号、自主次数、申请状态和已批准时长；不能借此恢复第三次申请机会。

## 三端实现

- 共享 protobuf 增加周期编号、申请、状态轮询、家长列表及决定消息。新功能需要 `0.4-parent-approval`（versionCode 5）孩子端。
- 服务端校验设备绑定和家长归属；每台设备每周期唯一一份申请，重复提交返回同一份；审批决定和设备执行确认幂等，已经处理的决定不能翻转。
- 服务端保存已下发的有效规则字段，最多保留设备新下发、当前执行和已缓存对应的三个版本，支持周期中改规则而不改变旧申请时长。不增加二进制图片存储列。
- 孩子端复用现有网络线程；有申请时最多约每 5 秒查询一次，收到批准并保存后再确认。普通心跳上报当前周期，答题结束后关闭旧周期待处理申请。
- 游戏提醒仍读取具有输入焦点的应用窗口包名，避免自身浮窗导致游戏暂停或反复收起，不读取游戏画面和聊天内容。

## 验证范围

Android 86 项测试通过，覆盖等待超过原时限、延迟批准后完整时长、提前批准保留旧时间、拒绝、仅一次额外申请、失败重试、写盘失败、重启、重复与旧周期回包，以及非游戏不享受等待豁免。服务端 71 项测试通过，新增审批归属、设备更换孩子时不继承旧审批、重复提交／批准／确认、拒绝、旧周期和冻结时长检查；保留原有图片不落库检查。前端协议生成、类型检查及生产构建通过。

真实 Android 11 虚拟机已实际完成两次自主延期、点击第三次申请、等待超过原时限仍继续游戏、家长接口批准、手机增加本次完整时长、确认执行及重复申请保护；记录保存在工作区 `outputs/第三次延期联调结果.json`，截图在 `outputs/parent-flow-*.png`。

另用明确标为“HTTP 界面验收样本（非手机）”的请求，在虚拟机 Chrome 83 中实际操作家长表单与审批按钮：保存每次 2 分钟后，原有周期仍按 1 分钟批准；页面宽度 360 CSS 像素且无横向溢出。修复了较旧 Chrome 不能解析默认 JavaScript 构建产物而白屏的问题，JS／CSS 构建目标现兼容 Chrome 80 和 Safari 14。页面记录在 `outputs/家长审批页面验收.json`，截图为 `outputs/parent-web-*.png`。此项界面样本与真实孩子端联调分开记录，没有把 HTTP 样本当作第二台真机。
